### 使用者

Execution工作區中, 如果要加入每個Test Case的執行進度條 (顯示在狀態按鈕上, 也就是PASS/FAIL按鈕上), 你會怎麼計算進度


### 助理結論（歷史）

我會用**目前測項已完成的工作量**計算進度。有明確總量就顯示百分比，沒有總量就顯示流動進度條。這樣看到 `50%`，就知道它代表完成了一半的檢查，而不是預測測試時間已經過了一半。

例如，RF-01-009 如果先列舉資源，再逐一檢查 URI 是否重複，可以這樣呈現：

| 測項執行情況 | 狀態按鈕顯示 |
|---|---|
| 正在列舉資源，總數未知 | `Running`，背景顯示流動條 |
| 確認共有 80 個資源，已檢查 32 個 | `40%`，背景填滿四成 |
| 80 個都已檢查，正在彙整結果 | `99%`，等待最終判定 |
| 收到最終結果 | 顯示 `PASS` 或 `FAIL`，移除進度條 |

**計算方式**是 `已完成數 ÷ 總數 × 100%`，執行中最多顯示 `99%`。分子和分母必須是同一種工作單位，例如「已檢查資源數／待檢查資源數」。如果第 32 個資源就觸發失敗並提前結束，按鈕直接顯示 `FAIL`，不必先跳到 `100%`。

在 BMCAgent 裡，我建議讓 Test Case **選擇性回報** `completed`、`total` 和目前步驟，由後端透過現有的執行事件傳給畫面。既有 Case 沒有回報進度時，仍可直接使用流動條。半自動或手動測項等待操作時，則顯示「等待輸入」，保留上次進度。

我不會用 Log 行數換算百分比。像 RF-01-009 一次就產生約 7.5 萬行，日誌多寡無法代表完成多少檢查。畫面更新可以沿用 Log 的合併更新方式，讓進度條平順，也避免每個事件都觸發重畫。
