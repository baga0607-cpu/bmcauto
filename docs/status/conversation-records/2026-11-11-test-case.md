### 助理結論（歷史）

可以在 `case.py` 加入 interface 選擇與 URL 組合規則，**但以目前平台流程，只改 case 還不夠**：BMCAgent 在執行 case 前就會檢查 BMC URL，裸 IP 會先被擋下，case 沒有機會補上 `https://`。

建議分成兩層責任：

| 層級 | 負責內容 | 範例 |
|---|---|---|
| BMCAgent 連線層 | IP、協定、port、帳密及 TLS 設定，產生完整連線位址 | `<private-ip>` → `https://<private-ip>` |
| `case.py` | 選擇使用的 interface，以及操作方法、路徑、headers、body | Redfish：`GET /redfish/v1/` |

因此，**case 宣告「我要使用 Redfish」並組合該測項的請求，是合理的；每支 case 自行補協定、解析連線設定，則不建議。** 後者會讓不同測項出現不同預設值，也增加日後修改 port、HTTPS 或 IPv6 支援的維護成本。

對目前 RF 測項，較合適的做法是讓平台統一接受裸 IP、預設 HTTPS，保留明確輸入的協定，再由 case 使用完整 base URL 組合 endpoint。若之後要支援 Redfish／SSH／IPMI 等 interface，也應由平台依 case 的需求準備連線，避免所有 case 都先強制登入 Redfish。
