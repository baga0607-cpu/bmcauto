# Execution activity and immediate stop, 2026-11-03

Execution labels use the latest real worker event. A running row shows Running for the first three seconds after activity, then IDLE: Ns. The one-second frontend clock uses existing stream events and summaries. Heartbeats and refreshing the summary do not advance the activity timestamp. The label opens Result Annotation as before.

The server admits one case per Task, supervises its Python process, and persists the received evidence and stopped outcome before releasing the worker. A Windows job contains the case and its local helpers. The case waits for admission to that job before executing user code. On POSIX the supervisor uses a dedicated process group. A stop signal wakes the supervisor without polling. Row Stop leaves the remaining selection available to the browser queue. Task Stop ends the selection. An interrupted row returns to NR, with Stopped recorded in its test log. An already-issued DUT operation can outlive local cancellation. DUT rollback is a proposed separate feature.

Validation on Windows used temporary databases, a fake SDK and isolated case files. A case blocked in a 60-second sleep and its spawned helper both stopped, previously emitted evidence was retained, the next case passed after a row stop, and a Task stop rejected the next case. Interactive input crossed the child process boundary. Invalid/stale stop targets were rejected. The targeted backend run passed 24 tests, followed by a five-test process run including the additional input test. The Execution controls browser fixture passed the idle threshold, heartbeat exclusion, reset on log activity, and existing stop-scope assertions. The large log regression passed with a maximum heartbeat gap of 60 ms. No physical DUT ran. A broader legacy PDF assertion still expected current-fw in report text. Three outdated evidence checks were updated to read the existing results endpoint and passed individually.

Local deployment verified zero active Tasks and backed up SQLite before restarting. GET /api/tasks returned HTTP 200, SQLite integrity was OK, and there were no foreign-key violations. Verification outputs and backup are under bmca-runtime/verification/idle-stop.
